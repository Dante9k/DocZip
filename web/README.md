# DocZip 本地网页版

通过本机网页批量压缩 DOCX 内嵌图片。无需安装 Word、无需登录、无需互联网；文件在浏览器的独立工作线程处理，不上传到服务器。

## 直接使用（Windows x64）

1. 将 `DocZip-Web-1.0.0-Windows-x64.zip` 完整解压。
2. 双击 `start.cmd`，浏览器会自动打开本机地址，默认 `http://127.0.0.1:4173`。端口被占用时自动选择下一个可用端口，以启动窗口显示的地址为准。
3. 选择保存文件夹，或切换为“下载结果”；选择压缩档位，添加 `.docx`，点击“开始压缩”。
4. 使用期间保留启动窗口。结束时按 Ctrl+C 或关闭该窗口。

完整压缩包包含 Node.js 运行环境，无需另外安装。服务只监听本机回环地址，不向局域网开放，也不接收文档上传。请使用最新版 Chrome 或 Edge；浏览器不支持文件夹访问时自动改为下载。浏览器授权的文件夹不会在下次打开时自动恢复，需要重新选择。

## 使用说明

- 每份文档一个任务，按顺序逐个处理；可以追加、暂停、继续、取消和删除等待任务。
- 暂停在当前文件结束后生效；运行与暂停期间锁定保存方式和压缩档位。
- 默认在选择的文件夹生成 `原文件名_light.docx`，检测到重名时依次增加 `_1`、`_2`。
- 文件夹写入失败时，已完成的压缩结果仍可以下载。
- 下载模式支持逐个下载和打包 ZIP。刷新、关闭网页或清除任务会释放结果，请先保存所需文件。浏览器自行处理下载目录中的重名文件。
- 文件夹写入使用浏览器事务写入流，正常取消或写入失败会中止写入并清理空占位文件。浏览器没有原子“文件不存在才创建”接口；请勿让多个网页或其他程序同时向同名输出写入。需要严格处理并发文件竞争时请使用桌面版。

## 压缩与保护

| 档位 | JPEG 质量 | 最大像素长边 |
|---|---:|---:|
| 清晰优先 | 90 | 3200 |
| 均衡 | 82 | 2400 |
| 体积优先 | 70 | 1600 |

只替换更小的 JPEG/PNG 编码内容，不修改图片名称、格式和引用；校验全部非图片部件解压后内容一致。像素长边上限与 Word 中的显示尺寸不同，显示宽高、位置、环绕、裁剪和旋转数据不变。JPEG 保留原始 EXIF 方向和 ICC 信息，不自动旋转；PNG 保留透明度和可用色彩信息，未缩小尺寸时保持像素无损。

灰度、CMYK、非 8 位、动画及其他不能安全处理的图片保留原样并说明原因。GIF、SVG、WMF、EMF、TIFF、外链图片及附件不压缩。没有变小的文档输出原文件完整副本；加密、签名、损坏文档拒绝处理。旧 `.doc` 不支持。

网页版安全上限：单文档 200 MiB、解压总量 256 MiB、10,000 个部件、单部件 64 MiB、单 XML 8 MiB、单图片编码 48 MiB / 1,600 万像素；单任务最长 3 分钟。超过图片上限会跳过该图；大文档建议使用桌面版。

自动内容校验不等同于 Word 视觉验收。交付环境未安装 Word，仍需在同一 Word 环境核对实际业务文档的页数、图片位置、显示尺寸及画质。

## 从源码运行

需要 Node.js 24 和 pnpm 11：

```powershell
pnpm install
pnpm build
pnpm start
```

`src/compress.ts` 负责 DOCX 校验与图片替换，`src/images.ts` 负责图片编码与元数据保留，`src/worker.ts` 是独立压缩线程，`src/queue.ts` 管理串行队列和保存。此目录可独立构建；服务程序仅使用 Node 内置模块。

仓库根目录的 `tests/web.test.mts` 测试浏览器版压缩核心；`scripts/web-test.mjs` 提供 Playwright 界面测试，需本地服务运行及可启动的 Chrome，可用 `CHROME_PATH` 指定路径。`node scripts/build-web-qa.mjs` 生成浏览器集成检查页，在本地服务的 `/qa.html` 运行（使用合成文档和浏览器私有测试文件夹，测试结束清理）；检查实际文件流保存、取消、串行队列、压缩后全部非图片内容、PNG 透明度、下载数据及写入异常。该检查页不进入交付包。`scripts/package-web.mjs` 生成包含运行时的免安装包。
